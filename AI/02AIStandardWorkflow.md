# iOS 开发 AI 编码标准流程
## 一、文档说明
本流程聚焦 iOS 原生开发（Swift/SwiftUI/UIKit）场景，融合「MCP对接蓝湖界面开发」专属适配、「AI主动反问澄清需求」核心优化，以「规格先行、分步执行、自检闭环」为核心逻辑，结合 AI 工具提升开发效率与代码质量，满足团队协作可追溯、版本管理规范化的要求。

## 二、基础信息
### 1. 适用范围
Swift / SwiftUI / UIKit 原生开发场景，包含：
- 新功能开发（如登录、支付模块）；
- BUG 修复（如页面崩溃、接口异常）；
- 迭代优化（如性能提升、包体积缩减）；
- 界面开发（含 MCP 对接蓝湖场景）。

### 2. 推荐工具
Mac + Cursor（支持本地文件读写、分步指令交互），兼容 Xcode 内置 AI 插件（XcodeGPT）、ChatGPT/文心一言等 AI 工具。

### 3. 核心原则
先规格、后编码、分步执行、自检闭环，支持 AI 主动反问澄清需求模糊点。

### 4. 流程边界
| 场景类型               | 流程执行要求                                                                 |
|------------------------|------------------------------------------------------------------------------|
| 新功能开发             | 严格执行全流程（准备→脑暴&澄清→Spec→计划→编码→自检→提交）|
| BUG 修复               | 简化脑暴/Spec 内容，聚焦「复现步骤→根因→修复方案」|
| 界面开发（MCP+蓝湖）| 执行全流程，脑暴环节使用专属模板，强化 UI 还原、MCP 对接维度                 |
| 极小改动               | 经团队共识后可跳过 Spec 编写，需在 Git 提交备注中明确说明（如文案修正、资源替换） |

## 三、【0 准备】：前置条件与目录规范
### 1. 核心要求
除极小改动外，所有需求/BUG 修复/界面开发必须执行本流程，确保开发有依据、可追溯。

### 2. 前置条件
| 场景类型               | 前置条件                                                                 |
|------------------------|--------------------------------------------------------------------------|
| 新功能开发             | 产品 PRD 已评审、核心交互逻辑团队达成共识                               |
| BUG 修复               | 明确 BUG 复现步骤、影响范围（如机型/系统版本）、严重等级                 |
| 迭代优化               | 明确优化指标（如列表加载耗时≤2s、包体积减少5%、FPS≥60）|
| 界面开发（MCP+蓝湖）| 蓝湖标注已确认、MCP 接口协议文档已对接、UI 适配规则（多机型/暗黑模式）已明确 |

### 3. 目录规范
AI 相关文件统一存放至项目根目录，分层管理：
```
项目根目录/
└── AI/
    ├── 03Specs/        // 规格文件主目录
    │   ├── feature/    // 新功能规格（例：登录、支付）
    │   ├── bugfix/     // BUG 修复规格（例：首页崩溃、接口异常）
    │   ├── optimize/   // 迭代优化规格（例：列表性能、包体积）
    │   ├── ui/         // 界面开发（MCP+蓝湖）规格（例：登录页、首页UI）
    │   └── example/    // 流程示例文件（新手参考）
    └── 04Temp/         // 临时脑暴/调试内容（可选）
```

## 四、【1 需求脑暴&澄清（含AI反问）】：明确边界与核心逻辑
### 1. 目标
梳理需求边界、核心逻辑、异常场景，通过 AI 主动反问澄清模糊点，避免后续开发返工。

### 2. 核心优化说明
允许 AI 针对需求中不明确、有歧义的点主动反问，开发者逐一解答后，AI 基于答复完成最终脑暴输出，确保内容无模糊点；若 AI 无反问，直接校验脑暴内容完整性即可。

### 3. 操作步骤
#### 步骤1：发送结构化脑暴指令
根据场景选择对应模板，在 Cursor 中发送指令（所有模板已内置 AI 反问授权）：
##### 模板1：通用新功能脑暴
```
我是iOS原生开发者（Swift/SwiftUI/UIKit），当前需求类型：新功能，具体需求：【填写产品PRD核心描述】
请基于iOS 开发最佳实践（兼容iOS 14.1）完成结构化脑暴，输出以下内容：
1. 功能边界（明确做/不做，避免模糊范围）；
2. 核心逻辑（页面/组件交互流程、核心方法设计、接口依赖）；
3. 数据结构（Model 定义、本地/网络数据格式、存储方案）；
4. 异常场景（网络异常/权限缺失/数据为空/版本兼容/接口报错）；
5. 技术方案（第三方库选型、性能/安全/隐私考量）；
6. 改动文件（预估涉及的文件路径/类名，便于后续拆分）；
7. 验收标准（功能/性能/兼容需达标的具体条件）。
针对需求中不明确、有歧义或需补充的信息，你可以主动向我反问，我会逐一解答，确保脑暴内容完整且贴合实际开发场景。
```

##### 模板2：BUG 修复脑暴
```
我是iOS原生开发者（Swift/SwiftUI/UIKit），当前需求类型：BUG修复，具体信息：
- 复现步骤：【填写详细复现步骤】
- 影响范围：【例：iOS 14.1机型、首页列表加载场景】
请完成结构化脑暴，输出以下内容：
1. 根因分析（推测BUG产生的技术原因）；
2. 修复思路（核心修复逻辑、避免影响其他功能）；
3. 异常覆盖（修复后需验证的边缘场景）；
4. 改动文件（预估涉及的文件路径/类名）；
5. 验收标准（验证方式、防回归措施）。
针对BUG复现条件、业务逻辑约束等不明确的点，你可以主动向我反问，确保修复方案精准无遗漏。
```

##### 模板3：迭代优化脑暴
```
我是iOS原生开发者（Swift/SwiftUI/UIKit），当前需求类型：迭代优化，具体需求：【填写优化背景+当前问题】
请基于iOS 开发最佳实践（兼容iOS 14.1）完成结构化脑暴，输出以下内容：
1. 优化思路（核心调整逻辑、第三方库/API 替换方案）；
2. 数据结构优化（缓存策略、模型精简、数据解析优化）；
3. 性能对比指标（优化前/后预期数值，如加载耗时、内存占用）；
4. 异常兼容（优化后版本/机型兼容场景）；
5. 改动文件（预估涉及的文件路径/类名）；
6. 验收标准（优化后达标指标、验证方式）。
针对优化目标、技术约束等不明确的点，你可以主动向我反问，确保优化方案可落地。
```

##### 模板4：界面开发（MCP对接蓝湖）专属脑暴
```
我是iOS原生开发者，当前需求：【填写界面开发需求，例：开发登录页，基于蓝湖标注+MCP接口对接】
请基于MCP对接蓝湖的场景做完整脑暴，需覆盖以下维度：
1. 功能边界：界面核心交互、与后端MCP接口的联动逻辑；
2. 蓝湖关联：蓝湖标注的UI参数（尺寸/颜色/字体/间距）、切图使用规范、标注异常点；
3. MCP对接：MCP接口协议解析、数据字段映射、接口调用时机/异常处理；
4. 页面/组件逻辑：组件复用、布局适配（多机型/暗黑模式）、动效还原；
5. 异常场景：MCP接口请求失败、蓝湖标注缺失/冲突、UI适配异常的兜底方案；
6. 技术方案：UI框架选型（SwiftUI/UIKit）、MCP对接封装方式、UI还原精度保障方案；
7. 改动文件：涉及的页面/组件/网络层文件清单。
允许你针对以上维度中不明确、有歧义的点向我反问，以澄清需求边界。
```

#### 步骤2：脑暴结果确认
1. 优先接收 AI 反问内容，逐一明确答复；
2. AI 基于答复完成最终脑暴输出，确认内容无模糊点；
3. 将脑暴内容同步至产品、测试、技术负责人，确认无异议后进入下一步。

## 五、【2 编写规格文件（Spec）】：落地开发依据
### 1. 目标
将脑暴内容转化为结构化、可落地的规格文档，作为开发唯一依据。

### 2. 命名规则
规格文件命名需包含「功能/BUG/UI标识+编号+版本+日期」，示例：
```
// 新功能
login_sms_001_v1_20240520.spec
// BUG修复
home_crash_empty_001_v1_20240520.spec
// 迭代优化
list_load_perf_001_v1_20240520.spec
// 界面开发（MCP+蓝湖）
login_ui_mcp_001_v1_20240520.spec
```

### 3. 模板规范
| 模块         | 新功能填写要求                          | BUG 修复填写要求                          | 迭代优化填写要求                          | 界面开发（MCP+蓝湖）填写要求                          |
|--------------|-----------------------------------------|-------------------------------------------|-------------------------------------------|-------------------------------------------------------|
| 需求背景     | 功能价值、关联PRD、核心目标             | 复现步骤、影响范围、根因分析              | 优化背景、当前问题、量化优化指标          | 界面价值、蓝湖/MCP 对接背景、UI 还原核心目标           |
| 核心逻辑     | 交互流程、核心方法、接口依赖            | 修复思路、关键代码逻辑、防回归设计        | 优化方案、核心调整逻辑、预期效果          | UI 交互流程、MCP 接口联动逻辑、动效还原规则            |
| 数据结构     | Model 定义、接口格式、存储规则          | 涉及的数据/配置项、数据异常点             | 数据结构优化点（缓存/模型/解析）          | MCP 接口字段映射、UI 数据绑定规则                      |
| 异常处理     | 全场景异常兜底（提示/降级/重试）        | 修复后异常覆盖场景、兜底措施              | 优化后异常兼容方案                        | MCP 接口异常、蓝湖标注异常、UI 适配异常的兜底方案      |
| 改动范围     | 涉及文件/类名、代码量预估                | 改动文件、修复范围、影响模块              | 改动文件、优化范围、性能对比指标          | 涉及的UI/网络/组件文件、代码量预估                    |
| 验收标准     | 功能/性能/兼容量化达标条件              | 测试用例、防回归措施                      | 优化后达标指标（如加载耗时≤2s）、验证方式 | UI 还原精度（像素级）、MCP 接口联调通过率、适配覆盖度  |

### 4. 操作步骤
#### 步骤1：新建 Spec 文件
在对应场景目录下创建文件（如 `AI/03Specs/ui/login_ui_mcp_001_v1_20240520.spec`）。

#### 步骤2：生成规格文档
在 Cursor 发送以下指令，将脑暴内容转化为规格文档并写入文件：
```
读取刚才的脑暴内容，按照以下模板生成iOS开发规格文档，内容精简、可落地，写入文件：【Spec文件路径】
【模板】
# 规格文档：【功能/BUG/UI名称】
## 1. 需求背景
【填写对应内容】
## 2. 核心逻辑
【填写对应内容】
## 3. 数据结构
【填写对应内容】
## 4. 异常处理
【填写对应内容】
## 5. 改动范围
【填写对应内容】
## 6. 验收标准
【填写对应内容】
```

#### 步骤3：规格文档审核
由技术负责人评审 Spec 文档，确认技术方案、改动范围合理后，进入下一步。

## 六、【3 拆解开发计划】：降低开发风险
### 1. 目标
将整体开发任务拆分为「可独立编译运行」的小步骤，避免一次性全量开发导致的风险。

### 2. 操作步骤
在 Cursor 发送指令，基于 Spec 文件拆解分步计划，并追加至 Spec 文件的「7. 开发计划」模块：
```
读取规格文件：【Spec文件路径】
为我拆解iOS开发分步执行计划，要求：
1. 每一步可独立编译运行，粒度细化到「单一功能模块」（如Model编写、网络层、UI层）；
2. 标注每步依赖项（如是否依赖接口联调/蓝湖切图/第三方库）；
3. 预估每步开发时长（可选）；
4. 将计划追加写入上述Spec文件的「7. 开发计划」模块。
```

### 3. 计划示例（界面开发MCP+蓝湖）
```
7. 开发计划
步骤1：编写MCP接口Model（无依赖）
步骤2：封装MCP接口请求工具类（依赖步骤1完成）
步骤3：基于蓝湖标注编写登录页UI骨架（无依赖）
步骤4：绑定UI与MCP接口数据（依赖步骤1-3完成）
步骤5：处理MCP接口异常/UI适配异常（依赖步骤1-4完成）
步骤6：还原登录页动效、校验UI还原精度（无依赖）
```

## 七、【4 分步编码】：按计划落地开发
### 1. 核心要求
严格按开发计划分步开发，禁止一次性全量生成代码，确保每步可验证。

### 2. 操作步骤
#### 步骤1：发送分步编码指令
针对每一步骤，在 Cursor 发送定制化编码指令（示例为「界面开发-蓝湖UI骨架编写」）：
```
按照规格文件 【Spec文件路径】 中的开发计划，执行第3步：基于蓝湖标注编写登录页UI骨架
要求：
1. 语言：Swift 6.1.2（项目适配版本）；
2. 兼容：适配iOS 14.1，支持暗黑模式；
3. 代码风格：类名大驼峰、方法小驼峰，Optional 安全解包；
4. UI还原：严格遵循蓝湖标注的尺寸/颜色/字体/间距，切图使用规范；
5. 注释：核心UI组件、布局约束必须加文档注释（/// 格式）；
6. 输出：完整可编译的UI代码，附带本地验证UI还原度的方式。
```

#### 步骤2：分步验证
每完成一步，先本地编译运行，验证无语法错误、核心逻辑/UI还原达标后，再执行下一步。

#### 步骤3：代码整合
所有步骤完成后，整合代码，确保模块间交互正常。

## 八、【5 代码自检】：全维度校验质量
### 1. 目标
覆盖语法、性能、安全、UI还原等维度，提前发现并修复问题，降低提测后返工率。

### 2. 操作步骤
#### 步骤1：AI 全维度自检
在 Cursor 发送自检指令，输出「问题列表+修复后代码」（界面开发需追加UI/MCP专项校验）：
```
检查以下iOS Swift代码（粘贴代码片段/指定文件路径），按维度逐一校验：
1. 语法规范（Swift版本兼容、Xcode警告/错误、语法正确性）；
2. 内存管理（强引用循环、Optional 安全解包、内存泄漏风险）；
3. 线程安全（UI操作主线程、多线程数据访问加锁）；
4. 异常处理（网络/存储/权限异常兜底、接口报错提示）；
5. 代码规范（命名规则、注释完整性、代码复用性）；
6. 性能优化（冗余计算、重复网络请求、UI渲染卡顿）；
7. 安全合规（隐私数据加密、权限申请、数据脱敏）；
8. 测试友好（单元测试适配性、关键方法可Mock）；
9. UI专项（蓝湖标注还原精度、多机型适配、暗黑模式兼容）；
10. MCP专项（接口字段映射准确性、请求时机合理性、异常兜底）。
要求：列出所有问题，标注严重等级（高/中/低），并输出修复后的完整代码。
```

#### 步骤2：工具自动校验
执行 SwiftLint 工具，修复语法/规范类问题：
```bash
# 终端执行校验
swiftlint lint
# 自动修复可修复问题
swiftlint autocorrect
```

#### 步骤3：人工复核
核心功能（支付、登录）、隐私相关、UI核心页面代码，需由技术负责人人工复核。

## 九、【6 提交 & 归档】：可追溯与规范化
### 1. 分支规范
按需求类型创建专属开发分支，命名规则：
```
# 新功能
feature/[功能名]-[编号]  例：feature/login-sms-001
# BUG修复
fix/[BUG描述]-[编号]     例：fix/home-crash-empty-001
# 迭代优化
perf/[优化点]-[编号]     例：perf/list-load-perf-001
# 界面开发（MCP+蓝湖）
ui/[界面名]-mcp-[编号]   例：ui/login-mcp-001
```

### 2. Git 提交规范
遵循 Conventional Commits 规范，备注关联 Spec 文件，示例：
```bash
# 新功能提交
git add .
git commit -m "feat(login): 实现短信登录功能 关联AI规格：AI/03Specs/feature/login_sms_001_v1_20240520.spec"

# BUG修复提交
git commit -m "fix(home): 修复首页数据为空崩溃问题 关联AI规格：AI/03Specs/bugfix/home_crash_empty_001_v1_20240520.spec"

# 迭代优化提交
git commit -m "perf(list): 优化列表加载性能（耗时从5s降至2s） 关联AI规格：AI/03Specs/optimize/list_load_perf_001_v1_20240520.spec"

# 界面开发（MCP+蓝湖）提交
git commit -m "feat(login-ui): 完成登录页UI开发（MCP+蓝湖） 关联AI规格：AI/03Specs/ui/login_ui_mcp_001_v1_20240520.spec"
```

### 3. 归档追溯
1. Spec 文件随代码同步提交至 Git，永久沉淀；
2. 将 Spec 文件链接同步至 Jira/飞书等工具，关联对应需求/BUG 单号；
3. 分支合并主分支前，需完成「Spec 审核+代码自检+人工复核」全流程。

## 十、配套机制：保障流程落地
### 1. 流程示例化
在 `AI/03Specs/example/` 目录下存放完整示例文件（含通用新功能、BUG修复、MCP+蓝湖界面开发），包含脑暴、规格、开发计划全内容，降低新开发者学习成本。

### 2. 流程迭代
每季度复盘流程痛点（如 Spec 编写耗时过长、AI 反问效率低、UI 还原校验遗漏），结合团队反馈微调步骤/模板，适配实际开发场景。

### 3. 工具适配
兼容各类 AI 工具（Cursor/XcodeGPT/ChatGPT），核心要求：指令结构化、支持反问交互、结果可落地。
